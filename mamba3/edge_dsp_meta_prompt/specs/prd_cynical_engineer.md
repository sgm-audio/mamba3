# Product Requirements Document (PRD)
## Concept A: The Self-Correcting Defensive Channel Strip ("The Cynical Engineer")

---

## 1. Executive Summary

### 1.1 Product Vision
"The Cynical Engineer" is a next-generation professional audio CLAP plugin designed to act as an automated, defensive, and context-aware channel strip. Instead of applying generic enhancement or subjective "color," this plugin acts strictly as a corrective operator. Guided by a core "Cynical Constitution," it continuously measures the incoming audio in real-time, infers dynamic corrections (using a quantized state-space neural model in the background), and renders those changes using mathematically phase-coherent and transient-perfect classical DSP algorithms.

### 1.2 The Problem Statement
Existing audio AI plugins operate on a "generative" paradigm (e.g., waveform-to-waveform autoencoders) which introduces severe phase smearing, destroys transient front-ends, adds high-latency overhead, and lacks real-time safety. Furthermore, existing AI plugins are "blind islands" that have no context of timeline position, downbeats, or track relationships within the session.

### 1.3 The Solution: Asynchronous Hybrid Architecture
By splitting execution into a zero-allocation **Observer** in the hard real-time thread and a **Mamba3 Controller** in a background worker, "The Cynical Engineer" achieves zero added latency, absolute real-time safety, and sample-accurate parametric adjustments to a standard, high-fidelity classical DSP channel strip (Gate, EQ, Compressor, Saturator).

## 2. Core Axioms & Constitutional Guardrails

### 2.1 The Master Constitution (Layer 4)
The plugin's background processor runs under an immutable, hardcoded Master Constitution that dictates all inference:
1.  **Do No Harm**: The primary goal is to prevent audio deterioration (clipping, masking, resonance buildup, low-end mud).
2.  **Preserve the Performance**: Never try to make the audio sound "cool," "huge," or "colored." Preserve the human timing, volume changes, and phrasing.
3.  **Transient-Coherency First**: High-frequency transients must be passed through untouched. Compression must not flatten the front-end attack of dynamic instruments.
4.  **Cynical Minimalist Processing**: Apply the minimum possible processing to achieve the target correction. If a track requires no correction, the parameters must remain bypassed ($0\text{ dB}$ gain, flat EQ, open gate).
5.  **No Hallucinations**: The AI is prohibited from generating raw audio samples or introducing unmodeled frequency material. It only manages classical DSP knobs.

### 2.2 DSP Kernel Constraints (Layer 3)
*   **Stability**: All dynamic IIR filter coefficients generated by the model must reside in the stable region of the $z$-plane. Coefficients are generated via bilinear trapezoidal mapping.
*   **Nyquist Protection**: Dynamic EQ bands must be mathematically capped below the Nyquist frequency ($f_s/2$) to prevent aliasing.
*   **ADAA Requirement**: Any saturation or waveshaping applied must utilize first- or second-order Anti-Derivative Anti-Aliasing (ADAA) algorithms to suppress high-frequency intermodulation distortion.

## 3. Observer Specifications (Real-Time Feature Extraction)

The **Observer** runs inside the hard real-time audio callback. It must allocate **zero memory** and perform **no system calls or blocking operations**. It operates block-by-block (e.g., 64 samples at $44.1\text{ kHz}$) and extracts the following features:

### 3.1 Feature Vector Extraction (L0 Input)

| Feature Name | Algorithm / Description | Dimensionality | Buffer Latency |
| :--- | :--- | :---: | :---: |
| **True Peak Level** | Continuous sample peak detection with $4\times$ oversampling interpolation. | 1 | 0 samples |
| **Envelope Tracker (RMS)** | Fast/Slow leaky integrator tracking short-term and long-term signal power. | 1 | 0 samples |
| **Crest Factor** | Ratio of Peak-to-RMS level, used to classify transient density. | 1 | 0 samples |
| **Spectral Centroid** | Zero-allocation FFT-based calculation indicating spectral brightness center. | 1 | 1 block (windowed) |
| **Zero Crossing Rate** | Counts sign changes in the buffer, indicating noisiness vs. harmonicity. | 1 | 0 samples |
| **Learnable Band Energies** | 6 soft triangular bands log-spaced across the spectrum (sub-bass to air). | 6 | 1 block (FFT) |
| **Transient Attack Slope** | First derivative of the RMS envelope, highlighting sharp onset events. | 1 | 0 samples |

## 4. Processor AI Specifications (Background Inference)

The **Processor** runs on a dedicated background thread pool. It consumes features from the Observer via an SPSC ring buffer and computes the optimal control parameters.

### 4.1 Input Context Package (Layer 1 & 0)
*   **Observer Features**: The stream of L0 feature vectors generated by the real-time Observer.
*   **Timeline Position**: Exact sample offset from the start of the DAW session timeline.
*   **Tempo & Time Signature**: BPM and Grid divisions (quarter, eighth, sixteenth notes) passed via the host interface.
*   **Track Metadata**: String inputs describing track type (e.g., "Lead Vocal", "Kick", "Electric Guitar") mapped to static embeddings.
*   **Operations Log History**: Recurrent hidden state carrying over the past 4 seconds of parameter modifications.

### 4.2 Parameter Output Specification
The Processor must output a serialized stream of DSP parameters at a control rate of $100\text{ Hz}$ (every $10\text{ ms}$):

## 5. Auditor Specifications (Safety & Verification)

The **Auditor** runs in a parallel thread, intercepting the Processor's parameter output stream before it is committed to the active DSP engine.

### 5.1 Verification Engine Rule Set
1.  **Phase Warp Protection**: The Auditor calculates the group delay of the proposed EQ curves. If the group delay at any band exceeds $3\text{ ms}$, the filter "Q" parameter is widened to flatten the phase response.
2.  **Over-Compression Penalty**: If the proposed compressor threshold/ratio combinations result in a simulated gain reduction exceeding $6\text{ dB}$ for more than $200\text{ ms}$, the Auditor automatically scales down the ratio.
3.  **Gain Envelope Clamping**: Absolute protection against clipping. If the proposed output make-up gain could result in an output peak above $-0.1\text{ dBFS}$ (calculated using the Observer's true peak history), the make-up gain is clamped.
4.  **Confidence Gate**: The Auditor runs a micro-classification pass. If the classification confidence score of the input signal falls below 80% (i.e. highly complex, noisy, or corrupted signal), the Auditor forces a slow linear ramp back to a dry/bypass state.

## 6. Real-Time DSP Engine Specifications

The DSP engine is written in highly optimized Rust/C++ with SIMD intrinsics (AVX-512 / ARM NEON) and runs inside the hard real-time callback, consuming the parameters stored in the atomic triple-buffer.

### 6.1 Gate Module
*   **Type**: Zero-crossing aligned gate.
*   **Behavior**: Prevents clicking on envelope openings/closings by delaying gain adjustments until the next zero-crossing in the audio stream.

### 6.2 EQ Module
*   **Type**: 6-Band zero-delay feedback (ZDF) state-variable filters (SVF) with bilinear discretization.
*   **Poles**: Stable complex poles matching the user's Mamba-3 mathematical filterbank.
*   **Resolution**: Dynamic parameter updates are smoothed using a $100\text{ Hz}$ low-pass one-pole filter to prevent zipper noise.

### 6.3 Compressor Module
*   **Type**: Feedback-topology peak/RMS compressor with an adjustable knee.
*   **Envelope**: Zero-allocation dual-stage envelope tracker that calculates instantaneous compression levels on the audio thread.

### 6.4 Saturator Module
*   **Type**: Cubic polynomial waveshaper.
*   **Anti-Aliasing**: First-order Anti-Derivative Anti-Aliasing (ADAA) implemented by integrating the polynomial waveshaping function:
    $$F(x) = \int f(x) \, dx$$
    And evaluating the derivative at sample boundaries:
    $$y(n) = \frac{F(x(n)) - F(x(n-1))}{x(n) - x(n-1)}$$
    This prevents digital aliasing distortion under heavy saturation.

## 7. UI/UX & Controls Specification

### 7.1 Visual Philosophy
*   The UI must feel premium, using a **sleek dark mode** with vibrant HSL tailored accents (e.g., deep emerald green representing the Auditor, and cool cyan representing the Observer).
*   **No gimmicky knobs**: Simple, clear sliders for "Degree of Cynicism" (how aggressive the AI corrections are) and "Safety Level" (how sensitive the Auditor is).

### 7.2 The Immutable Operation Log View
A central window in the UI displays a scrolling timeline of all adjustments made by the plugin:

```
  [12:04:21.104]  NOTCH EQ  -3.2 dB @ 4.2 kHz  (Resonance suppression - Conf: 98%)
  [12:04:21.320]  COMPRESS  Threshold: -16dB   (Vocal sibilance attenuation)
  [12:04:21.410]  AUDITOR   Bypassed EQ band 3 (Phase safety limit reached)
  [12:04:22.050]  SATURATE  Drive: +2.1 dB     (Dynamic crest factor compression)
```

The user can click on any log entry to **freeze the parameters** at that specific state, **bypass the action**, or **adjust the scale** manually.

### 7.3 User Controls

| Control Name | Range | Description |
| :--- | :--- | :--- |
| **Cynicism Intensity** | 0% to 100% | Scales the depth of the proposed corrections (0% = dry bypass, 100% = full correction). |
| **Safety Margin** | 0% to 100% | Defines the Auditor's threshold for phase/gain intervention (0% = unconstrained AI, 100% = ultra-defensive classical DSP limits). |
| **Constitutional Focus** | Vocal / Drum / Bass / Master | Selects the active Layer 4 target configuration for the background Mamba3 model. |
