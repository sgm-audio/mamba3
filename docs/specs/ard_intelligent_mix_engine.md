## 2. Mathematical & Psychoacoustic Foundations

### 2.1 Psychoacoustic Masking & Bark Scale Excitation Curves

To perform transparent Dynamic Spectral Carving (DSC), the system models the human ear's critical bands. We map frequencies $f$ in Hz to the Bark scale $z$:
$$z(f) = 13 \arctan(0.00076 f) + 3.5 \arctan\left(\left(\frac{f}{7500}\right)^2\right)$$

The psychoacoustic masking threshold (excitation pattern) $B(z)$ generated by a masking frequency $z_m$ with sound pressure level $L_m$ is modeled as a triangular filter shape with frequency-dependent slopes. The spreading function $SF(z, z_m)$ is formulated as:
$$SF(z, z_m) = \begin{cases} 
      15.82 + 7.5 (z - z_m + 0.474) - 17.5 \sqrt{1 + (z - z_m + 0.474)^2} & z \le z_m \\
      15.82 + 7.5 (z_m - z + 0.474) - 17.5 \sqrt{1 + (z_m - z + 0.474)^2} - (z - z_m) (24 + \frac{230}{f(z_m)}) & z > z_m 
   \end{cases}$$

The dynamic masking threshold $T_i(z)$ for the target track $i$ under the influence of $K-1$ other tracks is the non-linear summation:
$$T_i(z) = 10 \log_{10} \left( 10^{T_{\text{abs}}(z)/10} + \sum_{j \neq i} 10^{(L_j(z) - SF(z, z_j))/10} \right)$$
Where $T_{\text{abs}}(z)$ is the absolute threshold of hearing in quiet.

If the spectral energy of track $i$ at band $z$ ($L_i(z)$) is below the cumulative masking threshold $T_i(z)$, it is deemed inaudible (masked). The dynamic EQ band is steered to reduce the masking energy of the offending tracks by:
$$\text{Cut}_{j}(z) = \min\left(0, \gamma \cdot \left[ T_i(z) - L_j(z) \right]\right)$$
Where $\gamma \in [0.1, 0.5]$ is the scaling parameter governing the carving depth.

### 2.2 Cross-Track Multihead Attention

The background Mixer AI aggregates feature vectors from $K$ active instances into a sequence matrix of shape $(K, T, D)$. The cross-track relationship is modeled using Scaled Dot-Product Multihead Attention.

Given:
*   Queries $Q = X W_Q$ representing target track spectral profiles.
*   Keys $K = X W_K$ representing blocking track spectral profiles.
*   Values $V = X W_V$ representing the volume states.

The attention weights representing dynamic masking intensity are:
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}} + M\right) V$$

Where:
*   $d_k$ is the dimensionality of the key vectors.
*   $M$ is a $K \times K$ causal priority matrix. Track priority levels (e.g. Vocal having highest priority) are added as large negative offsets to key paths, preventing low-priority tracks from attenuating high-priority tracks.

## 3. Multi-Instance Shared Memory Architecture

Multiple instances of the CLAP plugin must communicate with sub-millisecond latency. We utilize POSIX Shared Memory (`shm_open`) and memory-mapped files (`mmap`) structured under strict memory alignments.

### 3.1 Struct Layout (Cache-Line Padding)

To prevent cache-line thrashing (false sharing) on multi-core CPUs, each instance's shared memory block is padded to 64 bytes (the standard L1/L2 cache line width) and aligned.

```rust
#[repr(C)]
#[align(64)]
pub struct InstanceState {
    pub instance_id: u32,
    pub priority: u32,
    pub is_active: u32,
    pub rms: f32,
    pub peak: f32,
    pub centroid: f32,
    pub zero_crossings: u32,
    pub band_energies: [f32; 6],
    pub dynamic_gains: [f32; 6], // Written by Master instance, read by local RT callback
}

#[repr(C)]
#[align(64)]
pub struct SharedMixRegistry {
    pub magic: u32,                // 0x4D495833 ('MIX3')
    pub lock: AtomicU32,           // CAS spinlock for registration
    pub active_count: u32,
    pub master_instance_id: u32,
    pub instances: [InstanceState; 64], // Fixed capacity to prevent heap allocations
}
```

### 3.2 Lock-Free Spinlock Implementation (Compare-And-Swap)

When a new plugin instance is loaded, it must register itself in the `SharedMixRegistry`. Registration is protected by an atomic Compare-And-Swap (CAS) spinlock to prevent race conditions during DAW track duplication.

```rust
impl SharedMixRegistry {
    pub fn try_lock_register(&self) -> Result<u32, &'static str> {
        let mut attempts = 0;
        // Spin lock using CAS
        while self.lock.compare_exchange_weak(

            1,
            Ordering::Acquire,
            Ordering::Relaxed
        ).is_err() {

            if attempts > 1000 {
                return Err("Registration Lock Timeout");
```

## 4. Thread Topologies & Inter-Instance Synchronization

The Mixer thread runs on a single background worker thread spawned by the Master Instance (the instance loaded on the summing bus or Master fader).

```
   [Audio Callback 1] ──► Extract Features ──► Write to Shared Memory (InstanceState 1)
   [Audio Callback 2] ──► Extract Features ──► Write to Shared Memory (InstanceState 2)
   [Audio Callback 3] ──► Extract Features ──► Write to Shared Memory (InstanceState 3)
                                                     │
                                                     ▼
                                            [Shared Mix Registry]
                                                     │
                                                     ▼
                                            [Mixer Worker Thread]
                                            - Aggregates (3, T, 12)
                                            - Multihead Attention Pass
                                            - Write Dynamic Gains to SHM
                                                     │
                                                     ▼
   [Audio Callback 1] ◄── Read Dynamic Gains ◄───────┴───────────────────────────────┐
   [Audio Callback 2] ◄── Read Dynamic Gains ◄───────────────────────────────────────┤
   [Audio Callback 3] ◄── Read Dynamic Gains ◄───────────────────────────────────────┘
```

### 4.1 Summing Synchronization
*   Each local instance's audio callback reads the audio block, writes its local features to its assigned slot in `SharedMixRegistry`, and immediately reads the `dynamic_gains` written by the Mixer during the previous inference pass.
*   This introduces exactly **one block of control latency** (typically $<2.9\text{ ms}$ at $128$-sample buffer), which is mathematically smoothed using an exponential moving average (EMA) filter:
    $$\text{Gain}_{\text{smooth}}(n) = \alpha \cdot \text{Gain}_{\text{target}} + (1 - \alpha) \cdot \text{Gain}_{\text{smooth}}(n-1)$$
    Where $\alpha = 0.05$ ensures artifact-free transition.

## 5. Model Interface & Tensor Topologies

The Mixer model aggregates inputs into a single sequence tensor.

### 5.1 Multihead Attention Tensor Layout

#### Input Tensors
*   `tracks_features`: Shape `[1, 64, 100, 12]` (Batch, Max Tracks, Sliding Window Frame Size, Features). Type: `Tensor<f32>`.
*   `priority_matrix`: Shape `[1, 64, 64]` (Containing the dynamic masking priority values). Type: `Tensor<f32>`.

#### Output Tensors
*   `coordinated_gains`: Shape `[1, 64, 6]` (Coordinated attenuation gains per band for each active track). Type: `Tensor<f32>`.
